## Constraints

- MUST include InputName for form submission compatibility (FormData)
- MUST support InputId for optional DOM reference where a native input renders; SelectInput prefixes the multi-select option checkbox ids with it
- MUST support two-way binding via TwoWayStatePath for Alpine.js
- MUST include IsRequired flag and visual indicators
- MUST render hints through inputHint.templ so the tooltip stays keyboard and touch accessible
- MUST render the InputHint tooltip through the shared toolset tooltip so it teleports to the fixed body layer and a scroll container or a modal cannot clip it
- MUST resolve the select dropdown open direction through the shared toolset controller so the list never opens downward into an overflow-hidden container
- MUST keep the click event stopped on the single-mode option radios and close the list explicitly in commitFocusedOption: keyboard radio activation dispatches a click that would otherwise close the list on an arrow-key move, and the stopped click no longer reaches the list close handler
- MUST drive option navigation through the shared focusAdjacentOption helper, never native radio grouping: a dropdown whose InputName or SelectName is empty renders unnamed radios that form no group, so only Chromium happens to move focus and Firefox does not
- MUST bind the NumberRangeInputField box to its local draft, never to the state path: the slider watch clamps the path on every write, so a direct binding clamps half-typed values
- MUST treat OptionsOneWayStatePath as the exclusive option mode: when it is set, the static FlatOptions and LabelValueOptions rows do not render, and the trigger resolves its label from the same Alpine array
- MUST parse the MultiColumnRepeatableFieldset bulk textarea on every input event, so the bound row array and the hidden JSON input stay current without a separate commit step
- MUST keep the FileUploadInput File objects out of Alpine state: DataTransfer rejects a proxied File
- MUST keep each dropdown surface default as the literal bg-neutral-800/95 class so a static stylesheet build sees the token, and raise the open list above the data table sticky header
- MUST reserve space under floating actions through floatingActionWidthRemResolver, never a fixed padding class, so a FloatingButtonStyle size change keeps the text clearance in TextArea and InlineCheckboxGroup
- MUST validate each CronSchedule custom field against its own bounds in cronFieldIsValid before composing the expression, so an out-of-range part never reaches the hidden form input
- MUST pass the DateTimePicker bound start and end values into the Alpine factory as x-data call arguments, never through x-init: Alpine evaluates x-init before a provider-style x-data materializes, so an init that reads the enclosing scope fails with dateTimePickerInitFromPaths is not defined
- MUST guard the DateTimePicker writeback effect with the initialized flag, so the effect cannot write the seed drafts back into the bound paths during Alpine's initial flush

## Guidance

- SHOULD support hint/description text with configurable display (tooltip vs description)
- SHOULD support prefix and suffix affixes (left/right) with values or state binding
- SHOULD accept a shared uiToolset.TextCase value on labelled components to transform the label and placeholder
- SHOULD include proper error state styling and messaging support
