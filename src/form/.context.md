Form input components for collecting user data. All components support Alpine.js two-way binding and have accessibility features (labels and disabled states); applicable components also support hints.

## Summary

- README.md — Component list and usage snippets for the package
- checkboxInput.templ — Checkbox with square, rounded, or circular shapes, five sizes, box colors, label position, indeterminate state, error state with message, and static or Alpine-bound checked, disabled, and invalid states
- checkboxInput_test.go — Table-driven tests for the checkbox size classes and box border classes, plus render tests for the shape class and the error states
- inputField.templ — Text input with configurable type (text, email, number, date, etc.), a five-step size scale, label text case, hints, affixes, and affix width percentages
- toggleSwitch.templ — Toggle switch for boolean or array Alpine.js state with size, color, and label position settings
- inlineGroup.go — Shared orientation classes and the MaxVisibleOptions height cap for InlineRadioGroup and InlineCheckboxGroup
- inlineRadioGroup.templ — Radio button group with horizontal or vertical orientation; the shared label notches into the fieldset border like the other notched fields
- inlineCheckboxGroup.templ — Checkbox group with horizontal or vertical orientation, rendered from the shared CheckboxInput
- radioInput.templ — Single radio button input
- selectInput.templ — Dropdown select with flat or label-value options; single mode renders native radio rows that share the component InputName as their radio group, multi mode (IsMultiSelect) renders the shared styled checkbox rows and keeps the dropdown open per toggle; its dropdown surface keeps the literal bg-neutral-800/95 default class, takes a DropdownBackgroundColor token, the dropdown height classes, and MaxVisibleOptions, and paints above the data table sticky header
- selectDropdown.go — Shared dropdown height classes resolver and the MaxVisibleOptions height style, with the row height of each dropdown family
- selectInputState.js — Alpine.js data component for the select dropdown: open toggle, close, the multi-select summary formatter, and the open-direction decision that measures both sides up to the viewport and every clipping ancestor so the open list cannot render cut off
- searchableSelectInput.templ — Searchable select with a filter box, single or multi mode, text or tag display with tag color settings, optional custom values, and clear, no-matches, and loading rows; it owns the option row and dropdown the remote variant shares, and its dropdown surface follows the same literal-default, token, height class, and MaxVisibleOptions rule as SelectInput
- searchableSelectInput.go — Settings, option types, the selection, presentation, and expression resolvers, and the dropdown class resolver
- searchableSelectInputState.js — Alpine data component: filtering, selection, tags, custom values, the debounce lifecycle with a pending state, and the shared open-upward decision
- remoteSearchableSelectInput.templ — Remote searchable select that loads options from an OptionsUrl with debounce, a minimum query length with a prompt below it, stale-response discard, loading, empty, and error rows, and InitialOptions that label values already bound to the state until the user types
- passwordInput.templ — Password input with a reveal toggle, a configurable random password generator, a strength meter with color settings, and action buttons rendered through uiControl.Button with padding and min-width/min-height constraints in a boxed or plain style selected by ActionButtonStyle; each action button carries a tooltip and an accessible name
- passwordInputState.js — Alpine data component: reveal toggle, generator, strength scoring, and the clipboard copy with a language-matched toast that ends with an exclamation mark
- textArea.templ — Multi-line text input with five height steps, expand-to-3x toggle, focusable action buttons, and hints
- inputHint.templ — Shared hint renderer: focusable info-icon tooltip rendered through the shared toolset tooltip with ARIA wiring, or description line below the field

## Constraints

- MUST include InputName for form submission compatibility (FormData)
- MUST support InputId for optional DOM reference where a native input renders; SelectInput prefixes the multi-select option checkbox ids with it
- MUST support two-way binding via TwoWayStatePath for Alpine.js
- MUST include IsRequired flag and visual indicators
- MUST render hints through inputHint.templ so the tooltip stays keyboard and touch accessible
- MUST render the InputHint tooltip through the shared toolset tooltip so it teleports to the fixed body layer and a scroll container or a modal cannot clip it
- MUST resolve the SelectInput open direction inside its Alpine data component so the list never opens downward into an overflow-hidden container
- MUST keep each dropdown surface default as the literal bg-neutral-800/95 class so a static stylesheet build sees the token, and raise the open list above the data table sticky header

## Guidance

- SHOULD support hint/description text with configurable display (tooltip vs description)
- SHOULD support prefix and suffix affixes (left/right) with values or state binding
- SHOULD accept a shared uiToolset.TextCase value on labelled components to transform the label and placeholder
- SHOULD include proper error state styling and messaging support
