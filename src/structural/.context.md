Structural components for navigating and displaying structured data. Pagination and FilterBar work standalone; DataTable and Carousel compose both and refresh their content from a server URL. PageHeading and Card give pages one header block and one surface container. Tabs switch between content panels bound to one selected value.

## Summary

- README.md — Component list and usage snippets for the package
- card.templ — Surface container with MiddleContent and FooterContent slots, an optional header block, border radius (including none), padding, gap, shadow, ring, and color settings, and a TextCase header transform forwarded to HeaderBlock
- carousel.templ — Multi-item slider over a server page with a responsive items-per-view window that follows Tailwind's named breakpoints, prev/next arrows (outside or inside), dot indicators (top or bottom), a search box above or below the track, swipe, optional autoplay with pause-on-hover, the shared filter bar below the track, and the shared pagination footer; the track and the pagination swap together on refresh, the root carries hx-sync so a new refresh aborts the one in flight, the pagination carries hx-swap-oob so HTMX swaps it out of band, and the settings script renders inside the component root

## Constraints

- MUST NOT require HTMX: refresh uses htmx.ajax when window.htmx exists and fetch otherwise
- MUST mark the refresh target element with data-ui-data-table so the response fragment is selectable
- MUST mark the carousel body region (arrows, track, and dots) with data-ui-carousel and the pagination region with data-ui-carousel-pagination so one refresh response refreshes both, keep hx-swap-oob on the pagination targeting this component's own pagination id so HTMX swaps out of band without rewriting another carousel, and keep hx-sync on the component root so a new refresh aborts the one in flight
- MUST keep the carousel filter bar and search box outside the swapped regions so a refresh cannot steal focus from a field being typed in
- MUST keep DataTable client state (pageNumber, itemsPerPage, sortKey, sortDirection, searchQuery, filterValues, selectedRowIds) in the component root, outside the swapped region
- MUST keep Carousel client state (pageNumber, itemsPerPage, searchQuery, filterValues, windowStart, itemsPerView, itemsCount) in the component root, outside the swapped regions
- MUST render each component's settings script inside its own component root, so two components that share one query URL template and one set of filter keys still read their own settings
- MUST give each component an auto-generated id that is unique per render, so two components that share one query URL template and one set of filter keys keep their own radio groups and input names
- MUST derive the carousel items-per-view from the browser window width against Tailwind's named breakpoints, and contain the carousel viewport on the inline axis so the track width cannot feed back into the layout
- MUST render CarouselItemTooltip through the shared `uiToolset.TooltipAlpineStateOnce` and `uiToolset.TooltipSurfaceClassesResolver` so the item tooltip teleports to the fixed body layer and survives a scroll container, the transformed track, or a modal
- MUST render every interactive control with an accessible name and keyboard operation
- MUST keep filter chips on neutral colors so contrast stays above the WCAG AA threshold
- MUST keep the page number zero-based across DataTable, Pagination, and the {pageNumber} placeholder; ShouldUseOneBasedPageDisplay changes only the strip labels and the first page stays 0 in the bound state

## Guidance

- SHOULD debounce every table refresh through one timer, including filters and search
- SHOULD debounce every carousel refresh through one timer, including filters and search
- SHOULD regenerate the docs/assets/dataTableDemoRefreshFragments.json asset with the demo after DataTable markup changes
- SHOULD regenerate the docs/assets/carouselDemoRefreshFragments.json asset with the demo after Carousel markup changes
- SHOULD accept a shared uiToolset.TextCase value on components with labels or titles (Card, PageHeading, DataTable, Tabs)
- SHOULD keep the filter bar flush with the table so the pair reads as one component
- SHOULD keep the filter bar flush with the carousel so the pair reads as one component
