Structural components for navigating and displaying structured data. Pagination and FilterBar work standalone; DataTable composes both and refreshes its rows from a server URL. PageHeading and Card give pages one header block and one surface container.

## Summary

- README.md — Component list and usage snippets for the package
- card.templ — Surface container with MiddleContent and FooterContent slots, an optional header block, border radius (including none), padding, gap, shadow, ring, and color settings, and a TextCase header transform forwarded to HeaderBlock
- dataTable.templ — Generic table component (DataTable[Row]) with sortable headers, row selection, filters, a default search box, toolbar slots, pagination footer, loading state, and error state
- dataTable.go — DataTableSettings and DataTableColumnSettings types and their methods: client settings, id, page size, pagination label, density, text case, checkbox shape, checkbox size, and row stripe resolvers; the named density, alignment, sort direction, and page size types; and the URL placeholder constants. The alignment type carries the column alignment and justify class methods. The Initial* fields seed client state; HeaderClass, CellClass, RowClassResolver, and IsStriped carry styling; CheckboxCheckedColor and CheckboxUncheckedColor carry the selection color; PageNumber is zero-based and ShouldUseOneBasedPageDisplay only changes the strip labels
- dataTableState.js — Alpine data component: refresh URL builder, debounced refresh through htmx.ajax or fetch, selection helpers, sort cycling, sort icons
- dataTable_test.go — Table-driven tests for the client settings, filter values, alignment, justify, header text case, checkbox shape, checkbox size, row stripe, page size, pagination label, and id methods, plus a render test for the one-based page strip wiring
- filterBar.templ — Standalone filter bar with text, enum select, multi-enum select, number range, and date range editors plus removable chips
- filterBarState.js — Alpine component that reads filter values and exposes chip visibility, chip label, single-filter reset, clear-all, and any-active helpers
- pageHeading.templ — One heading component wrapping uiDisplay.HeaderBlock; Level page renders the h1 page header with page spacing, Level section renders the h2 section heading with icon-chip defaults; TextCase is forwarded to HeaderBlock
- pagination.templ — Page controls with readout, derived page-number strip, first/prev/next/last buttons, and items-per-page selector; the page-number controls hide on a single page while the readout and selector stay
- pagination.go — Default page-size choices plus the readout and page-count expression builders; the readout maps the zero-based page number to a one-based item range
- paginationState.js — Alpine helper that builds the page-number strip with first, last, and ellipsis items; indices run from 0 to pagesTotal-1 and labels add the display base
- pagination_test.go — Table-driven tests for the readout, page-count, and last-page-number expression builders
- sidebar.templ — Vertical navigation panel moved from src/display
- sidebar.go — Dynamic class expression builder: the is-inline attachment expression and the Alpine class toggles for visibility, collapse, attachment, off-canvas, side, and float
- sidebar_test.go — Table-driven tests for the is-inline attachment expression and the dynamic class combinations

## Constraints

- MUST NOT require HTMX: refresh uses htmx.ajax when window.htmx exists and fetch otherwise
- MUST mark the refresh target element with data-ui-data-table so the response fragment is selectable
- MUST keep DataTable client state (pageNumber, itemsPerPage, sortKey, sortDirection, searchQuery, filterValues, selectedRowIds) in the component root, outside the swapped region
- MUST render every interactive control with an accessible name and keyboard operation
- MUST keep filter chips on neutral colors so contrast stays above the WCAG AA threshold
- MUST keep the page number zero-based across DataTable, Pagination, and the {pageNumber} placeholder; ShouldUseOneBasedPageDisplay changes only the strip labels and the first page stays 0 in the bound state

## Guidance

- SHOULD debounce every table refresh through one timer, including filters and search
- SHOULD regenerate the docs/assets/dataTableDemoRefreshFragments.json asset with the demo after DataTable markup changes
- SHOULD accept a shared uiToolset.TextCase value on components with labels or titles (Card, PageHeading, DataTable)
- SHOULD keep the filter bar flush with the table so the pair reads as one component
