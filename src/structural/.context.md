Structural components for navigating and displaying structured data. Pagination and FilterBar work standalone; DataTable composes both and refreshes its rows from a server URL.

## Summary

- README.md — Component list and usage snippets for the package
- dataTable.templ — Generic table component (DataTable[T]) with sortable headers, row selection, filters, search slot, toolbar slots, pagination footer, loading state, and error state
- dataTable.go — DataTableSettings and DataTableColumnSettings types and their methods: client settings, id, page size, pagination label, density, header case, checkbox shape, checkbox size, and row stripe resolvers; the named density, alignment, sort direction, header text case, and page size types; and the URL placeholder constants. The alignment type carries the column alignment and justify class methods. The Initial* fields seed client state; HeaderClass, CellClass, RowClassResolver, and IsStriped carry styling; CheckboxCheckedColor and CheckboxUncheckedColor carry the selection color
- dataTableState.js — Alpine data component: refresh URL builder, debounced refresh through htmx.ajax or fetch, selection helpers, sort cycling, sort icons
- dataTable_test.go — Table-driven tests for the client settings, filter values, alignment, justify, header text case, checkbox shape, checkbox size, row stripe, page size, page number, pagination label, and id methods
- filterBar.templ — Standalone filter bar with text, enum select, number range, and date range editors plus removable chips
- filterBar.go — Alpine expression builders for chip values, chip visibility, reset, and clear-all
- filterBar_test.go — Table-driven tests for the filter bar expression builders
- pagination.templ — Page controls with readout, page-number strip, first/prev/next/last buttons, and items-per-page selector
- pagination.go — Default page-size options and the readout expression builder
- paginationState.js — Alpine helper that builds the page-number strip with first, last, and ellipsis items
- pagination_test.go — Table-driven tests for the readout expression builder
- sidebar.templ — Vertical navigation panel moved from src/display

## Constraints

- MUST NOT require HTMX: refresh uses htmx.ajax when window.htmx exists and fetch otherwise
- MUST mark the refresh target element with data-ui-data-table so the response fragment is selectable
- MUST keep DataTable client state (pageNumber, itemsPerPage, sortKey, sortDirection, searchQuery, filterValues, selectedRowIds) in the component root, outside the swapped region
- MUST render every interactive control with an accessible name and keyboard operation
- MUST keep filter chips on neutral colors so contrast stays above the WCAG AA threshold

## Guidance

- SHOULD debounce every table refresh through one timer, including filters and search
- SHOULD regenerate the docs/assets/dataTableDemoRefresh fragments with the demo after DataTable markup changes
- SHOULD keep the filter bar flush with the table so the pair reads as one component
