Display components for presenting content and creating layouts. These are primarily presentational; state management is optional for components like modals and toasts.

## Summary

- README.md — Component list and usage snippets for the package
- accordion.templ — Collapsible section component for grouping content, with an optional single-open mode, an option that renders the first item open, and a shared TextCase title transform
- alert.templ — Alert/notification box with title, description, and icon variants (success, warning, error, info)
- chart.go — Chart settings split by chart kind: the shared ChartSettings with XAxis, Series, Tooltip, and the color and row options; ChartCartesianSettings for line, area, and bar (StackMode, AreaFillStyle, MarkerDisplayMode, YAxis); ChartDonutSettings for the donut (HolePercent, SliceIdentityColors, and the center label display mode, at-rest slice, size scale, value suffix, and colors); the option enums, the private chartConfig wire structs with their JSON tags, the resolvers that fill defaults and reject unknown options, the legend and tooltip class resolvers, and the color token collector
- chart.templ — Chart markup: HTML legend, plot canvas, empty state, tooltip, one hidden color probe per color token, and the screen-reader table
- chartState.js — Alpine chart component and the plain Vega spec builders: the color probe reader that normalizes every probed color to sRGB, the per-token fallback colors, row keys and order, the folded series points, the stack transform, voronoi hover with crosshair and markers, grouped and stacked bars, the Y-domain-clamped area and bar baselines, area fills, donut arcs with the optional slice name and value in the hole, the validated eight-color palette, the tooltip handler with the optional global JS content function, resize, the destroy guard across the probe wait, and the rows path watch with the row cap
- chart_test.go — Table-driven tests for the chart config resolver, the color token collector, the rendered parts, the hidden legend, and the settings errors
- cloakLoading.templ — Overlay to hide content while loading
- cloakLoadingState.js — Alpine cloak state that hides the overlay after Alpine initializes plus the configured delay
- confirmationDialog.templ — confirmationDialog engine plus the ConfirmDialog, WarningDialog, CriticalDialog, and DeleteDialog presets; delete and critical gate the confirm action behind typing the target name or id
- confirmationDialog.go — Tone resolver, target match path resolver, the type-to-confirm field label resolver, and the type-to-confirm disabled expression builder
- confirmationDialog_test.go — Table-driven tests for the tone, match path, and disabled expression helpers
- headerBlock.templ — Header block (title, sub-heading, icon, actions) with the HeaderSize scale, left or top icon placement, and a shared TextCase transform
- headerIcon.templ — Icon chip with color, background, padding, and radius settings
- loadingOverlay.templ — Full-screen overlay with loading indicator and a fade transition
- modal.templ — Dialog/modal component with header, content, footer, the viewport-percentage InitialSize scale that sets width and height together, the WidthPercent and HeightPercent overrides, the MinWidthPercent/MaxWidthPercent/MinHeightPercent/MaxHeightPercent viewport constraints, the ShouldHeightMatchContent content-height option, the middle-content scroll toggle, and the animated size transition
- tag.templ — Badge/label component for categorization with a bound value display, a tiny size for table cells, a shared TextCase label transform, an optional remove button, and a `rounded-md` default radius
- toast.templ — Dismissible notification component with Alpine.js state management, a `neutral-800/90` default surface, and a ring that takes the tone color (green success, yellow partial success, red danger)
- toastState.js — Alpine toast state with API response message display, the type-to-ring-color resolver, and HTMX handling

## Constraints

- MUST support nested templ.Component for content composition
- MUST use Phosphor icons for visual elements
- MUST support various size and styling variants
- MUST keep the Vega view and the resize observer out of the chart Alpine state: Alpine proxies every nested object of reactive state, and a proxied Vega view hangs the page
- MUST build chart specs for plain Vega only; the import package no longer loads Vega-Lite or vega-embed
- MUST take chart colors as Tailwind tokens and resolve them through the rendered probes; Vega needs real CSS colors, and the UnoCSS runtime only styles classes it finds in the page
- MUST normalize every probed chart color to sRGB through a canvas: a host page on Tailwind v4 or UnoCSS preset-wind4 computes tokens to oklch, which Vega cannot parse
- MUST give every chart color a fallback: an unresolved token would otherwise reach Vega as undefined and draw black or nothing
- MUST keep the JSON tags on the private chart wire structs, never on the public settings structs: the public structs hold HTML-only fields and Go callbacks that must not reach the client

## Guidance

- SHOULD support Alpine.js for interactive components (modal visibility, toast dismissal)
- SHOULD include optional left and right icons for alerts and badges
- SHOULD accept a shared uiToolset.TextCase value on components with labels or titles (Accordion, HeaderBlock, Tag)
- SHOULD provide both HTML and state-based binding options for content
