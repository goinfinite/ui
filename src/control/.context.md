Interactive control components — actions and adjustments, not form data collection. Each component configures itself through an all-optional settings struct and drives its visual state from a single Alpine.js `x-data` object.

## Summary

- README.md — Component list and usage snippets for the package
- button.templ — Button with label, aria label, left/right icons, five sizes, three shapes, color and ring styling, a shared TextCase label transform, disabled state, click handlers, an always-present type attribute, and a hover tooltip
- buttonTooltipState.js — Alpine data component that teleports the tooltip to the document body, positions it with fixed coordinates on hover or focus, and flips it to stay inside the viewport
- rangeSlider.templ — Range slider with min/max/step, single or dual thumbs, value bubbles, optional tick marks, start/end value labels, and per-thumb accessible names

## Constraints

- MUST render every button with a `type` attribute: `button` by default, `submit` when `IsSubmit` is set
- MUST render the button tooltip through buttonTooltipState.js in the fixed body layer; a scroll container must not clip it or gain a scrollbar from it
- MUST keep the native range inputs in rangeSlider.templ transparent, above the visual thumbs, and as tall as the thumb: they carry keyboard, screen-reader, and drag interaction for the visual thumbs
- MUST split the dual-mode pointer targets with the midpoint clip-path so each native input stays interactive only on its own side of the two thumbs
- MUST resolve rangeSlider.templ thumb aria-labels through `resolveRangeSliderThumbAriaLabel`, which falls back from the explicit aria-label to the thumb's own visible label to a default name
- MUST build both rangeSlider.templ two-way state watches through `resolveRangeSliderLowerWatch` and `resolveRangeSliderUpperWatch`; each corrects an out-of-bounds state path, and in dual mode pushes the sibling thumb one step past and corrects the sibling state path when the write crosses it
- MUST reuse those same helpers for `ShouldNormalizeInitialState`, which applies the corrections once at init and must stay after the watch registrations so the corrections reach the local thumb values

## Guidance

- SHOULD extend dual-thumb options in RangeSliderSettings with `ThumbUpper*` mirrors of the matching `Thumb*` fields instead of adding a second thumb render path
- SHOULD keep each thumb on its own two-way state path: the upper path is ignored without dual mode, and equal paths collapse both thumbs into one
