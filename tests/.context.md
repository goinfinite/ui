The project's test system. One entry point runs every registered suite inside a disposable environment.

## Summary

- tests.sh — Entry point and contract: selects registry nodes, serves the demo when a selected node requires it, runs suites, reports. Exit 0 pass, 1 failure, 2 runner error (including timeout)
- tests_test.sh — CLI contract for tests.sh: registry filters, rejected invocations, and the demo-server decision, all driven as subprocesses
- registry.yaml — Explicit registry of feature:scope/level nodes with run commands and a demo-server requirement flag. Trusted input: only repo writers may edit it
- golden.yaml — Golden performance budgets. The runner reads it and never rewrites it; fatal_ms promotion is a deliberate human edit
- lib/registry.mjs — Reads registry.yaml, applies level/feature/scope filters, prints list or selection
- lib/serveDemo.mjs — Localhost server for docs/ that rewrites external script, stylesheet, and image URLs to /proxy/ paths, proxies only hosts on its allowlist without following redirects, and serves them from a fetch-once cache in tests/.cache/demo-assets/, so specs never load assets from a CDN; used by tests.sh
- lib/checkPerformance.mjs — Compares performance-results.json against golden.yaml tiers (info/warn/fatal)
- ui/run.sh — Runs Playwright for one mode (smoke, standard, a11y, performance, toolset, control, structural-smoke, structural, structural-a11y, cross-browser, toolset-cross-browser, control-cross-browser, structural-cross-browser); requires DEMO_URL from tests.sh
- ui/run_test.sh — CLI contract for run.sh: rejected invocations and the DEMO_URL requirement
- ui/examplePanel.js — Shared Playwright helpers that resolve a demo Advanced Examples panel by its exact summary title and open it
- ui/playwright.config.js — Chromium, Firefox, WebKit projects with 3 workers; WebKit disabled in run.sh until host libraries exist
- ui/specs/ — Behavioral specs by feature: form (geometry and state assertions on rendered components), control (slider keyboard input, thumb drag, accessible names, tick marks), display (modal sizing and close behavior, confirmation dialog presets and the type-to-confirm gate, accordion cutout surface), structural (pagination, filter bar, data table refresh, debounce, error recovery, fetch fallback), toolset (JsonAjax payload guard and loading overlay), a11y (axe ratchet), performance (click-to-final-state latency medians)
- ui/a11y-baseline.json — Recorded axe violation counts per rule; growth fails, shrink is progress

## Constraints

- Levels are cumulative: fast ⊆ standard ⊆ exhaustive
- Every registered command MUST finish within the 30-minute ceiling
- Specs assert observable behavior (rendered geometry, input values, visibility), never private internals
- Playwright browsers install via `npx playwright install` inside tests/; node pins via .mise.toml
- At most 3 test processes run in parallel: tests.sh runs registered nodes one at a time, Playwright workers stay at 3, direct tool runs pass `--workers=3`, and the registered `go test` nodes pass `-p 3`

## Guidance

- Add a new suite by registering it in registry.yaml; do not add filesystem discovery
- Enter everything through tests.sh; run.sh refuses to work without DEMO_URL
- UI specs follow .agents/skills/test-writing-patterns/SKILL.md UI model: happy path, error/degraded state, edge interaction
