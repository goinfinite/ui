The project's test system. One entry point runs every registered suite inside a disposable environment.

## Summary

- tests.sh — Entry point and contract: selects registry nodes, serves the demo and starts the Lightpanda CDP server when a selected node requires the demo, runs suites, reports. Exit 0 pass, 1 failure, 2 runner error (including timeout and a missing lightpanda binary)
- tests_test.sh — CLI contract for tests.sh: registry filters, rejected invocations, the demo-server decision, and the Lightpanda start and binary check, all driven as subprocesses
- registry.yaml — Explicit registry of feature:scope/level nodes with run commands and a demo-server requirement flag. Trusted input: only repo writers may edit it
- golden.yaml — Golden performance budgets, measured on Chromium. The runner reads it and never rewrites it; fatal_ms promotion is a deliberate human edit
- lib/registry.mjs — Reads registry.yaml, applies level/feature/scope filters, prints list or selection
- lib/serveDemo.mjs — Localhost server for docs/ that rewrites external script, stylesheet, and image URLs to /proxy/ paths, proxies only hosts on its allowlist without following redirects, and serves them from a fetch-once cache in tests/.cache/demo-assets/, so specs never load assets from a CDN; used by tests.sh and demo/serveDemo.sh
- lib/checkPerformance.mjs — Compares performance-results.json against golden.yaml tiers (info/warn/fatal)
- ui/run.sh — Runs Playwright for one mode. The fast and standard modes (smoke, standard, toolset, control, structural-smoke, structural, structural-a11y) run the Lightpanda project with 3 workers. The exhaustive modes (a11y, performance, cross-browser, toolset-cross-browser, control-cross-browser, structural-cross-browser) run Chromium, then Firefox, with 1 worker. Requires DEMO_URL, and UI_TEST_LIGHTPANDA_CDP_URL for the Lightpanda modes
- ui/run_test.sh — CLI contract for run.sh: rejected invocations, the DEMO_URL requirement, and the Lightpanda endpoint requirement
- ui/fixture.js — The `test` and `expect` every spec imports. When UI_TEST_LIGHTPANDA_CDP_URL is set, the worker browser connects to Lightpanda over CDP
- ui/examplePanel.js — Shared Playwright helpers that open one demo Advanced Examples panel by its exact summary title, or every panel in a section, and wait until the lazy content loads; each open also dispatches the details toggle event, which Lightpanda never fires
- ui/playwright.config.js — Lightpanda, Chromium, Firefox, and WebKit projects. The Lightpanda project skips `@browser` tests and uses a very tall viewport; WebKit stays out of run.sh until host libraries exist
- ui/specs/ — Behavioral specs by feature: form (geometry and state assertions on rendered components), control (slider keyboard input, thumb drag, accessible names, tick marks), display (modal sizing and close behavior, confirmation dialog presets and the type-to-confirm gate, accordion cutout surface), structural (pagination, filter bar, data table refresh, debounce, error recovery, fetch fallback, carousel item tooltip teleport, keyboard reveal, modal stacking, and refresh leak), toolset (JsonAjax payload guard and loading overlay), a11y (axe ratchet), performance (click-to-final-state latency medians)
- ui/a11y-baseline.json — Recorded axe violation counts per rule; growth fails, shrink is progress

## Constraints

- Levels are cumulative: fast ⊆ standard ⊆ exhaustive
- Every registered command MUST finish within the 30-minute ceiling
- Specs assert observable behavior (rendered geometry, input values, visibility), never private internals
- A test that needs a full browser engine MUST carry the `@browser` tag: layout, geometry, computed styles, pointer coordinates, hover, named keys other than Enter and Space, native element behavior, or a second browser context. Lightpanda has no layout, drops the other named keys, and allows one context, so such a test fails or passes by accident there
- Lightpanda installs through .mise.toml; Playwright browsers install via `npx playwright install` inside tests/ and serve only the exhaustive modes
- At most 3 test processes run in parallel: tests.sh runs registered nodes one at a time, Lightpanda runs with 3 Playwright workers, Chromium and Firefox run with 1 worker, direct tool runs pass `--workers=3`, and the registered `go test` nodes pass `-p 3`

## Guidance

- Add a new suite by registering it in registry.yaml; do not add filesystem discovery
- Enter everything through tests.sh; run.sh refuses to work without DEMO_URL
- UI specs follow .agents/skills/test-writing-patterns/SKILL.md UI model: happy path, error/degraded state, edge interaction
- For backdrop and overlay behavior, dispatch the event on the element (`locator.dispatchEvent`) instead of a coordinate click, so the test runs on Lightpanda
