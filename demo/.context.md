Static HTML demo generation. Contains a templ-based showcase of all UI components with usage examples. The demo is built as a separate Go module to avoid circular imports.

## Summary

- demo.go — `demoGenerator`, the entrypoint that renders DemoIndex() to docs/index.html, the advanced example panels to one JSON asset per component section in docs/assets/advancedExamples/, and the data table and carousel refresh fragments to one JSON asset each in docs/assets/, writing each output only when its content changed
- advancedExamples.go — Render-time registry for the advanced example panels: DemoAdvancedExamples registers each panel and renders a placeholder, and the registry renders each panel alone so its asset holds the component scripts the panel needs
- advancedExampleLoader.js — Browser-side loader that fetches a panel from its section asset on the first open, skips the scripts the page already ran, and inserts the markup so Alpine, UnoCSS, and HTMX set it up
- demoIndex.templ — Page shell: the navigation sidebar, the nav header and items, and DemoIndex(), which composes the page and closes the file
- demoExample.templ — Shared example frame: UsageTitle, DemoExampleHeader, the side-by-side DemoExampleCard with the explanation and usage stacked in the left column, its stacked variant for wide examples, DemoAlpineStateBlock, DemoAdvancedExamples, the DemoComponentSection layout every component demo calls, and the Demo* class constants
- *Demo.templ — One file per component demo, for example checkboxInputDemo.templ. Each holds the component's usage examples above the XxxDemo() section that calls them
- data.go — Demo record type, 25 sample rows with descriptions, filter declarations, the live table settings builder that slices one page, and the static table builders for the advanced examples
- carouselDemo.templ — Carousel usage examples (styling, autoplay, server pagination and filters, item tooltips with the same carousel inside a modal), the CarouselDemo() section, the shared settings builder, the item tooltip wrapper, and CarouselRefreshFragment() that renders the carousel refresh regions for one page
- dataTableDemoRouting.js — Browser-side router that picks the pre-rendered table or carousel state for the requested page from the JSON asset and serves it as the refresh response
- serveDemo.sh — Starts, stops, or reports the local demo server (tests/lib/serveDemo.mjs) for manual inspection; defaults to port 8399 and refuses the suite port 8377
- serveDemo_test.sh — Behavior of serveDemo.sh: rejected ports and actions, and the start, status, stop lifecycle
- fileUploadDemoRouting.js — Browser-side XHR patch for the file upload demo URLs: it replays upload progress over two seconds and answers from a local static asset, so demo files never leave the browser; the error URL answers 404
- buttonDemoState.js — Alpine state for the button action states example: one click action that resolves, one that rejects, and a shared pending flag
- chartDemoState.js — Alpine state for the live chart example: a 20-row CPU and memory window that appends a row every two seconds
- multiColumnRepeatableFieldsetDemoState.js — Alpine state for the repeatable fieldset demo: a random row factory so every added row carries distinct values
- remoteSearchableSelectDemoRouting.js — Browser-side router that intercepts the demo's fetch calls and answers them from the bundled country list
- *_templ.go — Compiled templ output (auto-generated, gitignored)
- go.mod — Separate Go module to isolate demo dependencies
- go.sum — Dependency checksums

## Constraints

- MUST be a separate Go module to prevent circular dependencies with the main ui package
- MUST generate a static index.html file (not served as a live endpoint)
- MUST keep docs/index.html the only HTML file: the table and carousel refresh fragments live in one JSON asset each in docs/assets, and the browser router serves the requested page from them
- MUST keep the advanced example markup out of docs/index.html: the UnoCSS runtime scans the whole page before it injects styles, so the page size sets the time to the first styled paint
- MUST pass the section id to DemoAdvancedExamples; the id names the section asset, and each panel title must be unique inside its section
- MUST keep every demo file in package main, with an import block that lists only the ui aliases its body uses

## Guidance

- SHOULD showcase all components from src/ with realistic configurations
- SHOULD include navigation sidebar for easy browsing of component categories
- SHOULD demonstrate both basic and advanced usage patterns for each component
